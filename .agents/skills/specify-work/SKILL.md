# Specify work

Read any existing issue and relevant architecture. Clarify observable outcomes and resolve decisions that materially affect implementation. Use the repository issue form to write acceptance criteria that a reviewer can exercise. Split work only where each slice can be delivered on its own and link its dependencies. Keep the issue canonical when it exists. Create or update GitHub issues only with authorization.
