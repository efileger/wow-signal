# Specify work

Read any existing issue and relevant architecture. Clarify observable outcomes and resolve decisions that materially affect implementation. Use the repository issue form to write acceptance criteria that a reviewer can exercise. Size each issue using the small-batch working agreement in [AGENTS.md](../../../AGENTS.md). Each slice should deliver a verifiable outcome. Link dependencies and explain in the issue if a larger batch needs to stay together. Keep the issue canonical when it exists. Create or update GitHub issues only with authorization.
